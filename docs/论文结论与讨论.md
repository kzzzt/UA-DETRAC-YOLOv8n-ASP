## 一、主要结论（从零训练：6 变体 × 3 种子 × 100 轮）

1. **组合模型 `simam_p2` 在同口径（last.pt）下最优**：mAP50 0.9041 ± 0.0078、
   mAP50-95 0.7339 ± 0.0057，相对 baseline 分别 **+0.0059 / +0.0079**，但 **未达统计显著**（n=3）。
2. **唯一稳定的显著正向结果在"阴天"场景**：mAP50 上 `simam_p2` +0.0158\*、`asp` +0.0126\*；
   mAP50-95 上 +0.0155\* / +0.0133\*。机制解释可写：阴天光照对比度低、目标与背景差异弱，
   SimAM 的**能量式（无参数）注意力**更能在弱对比条件下突出车辆目标。
3. **EIOU 没有正增益，且是唯一显著的负向结果**：`eiou` 在夜间 mAP50-95 上 −0.0133\*；
   `asp`（SimAM+P2+EIOU）在 last.pt 上 mAP50 最低（0.8823）。说明三项改进**不是简单叠加**，
   这本身是一个有价值的消融发现。
4. **分目标尺寸：方向性正确但不显著**。AP_medium 的正向差异最大（`asp` +0.0198、`simam_p2` +0.0181），
   AP_large 基本持平（符合"改进针对中小目标"的预期）。**注意**：`p2` 的 AP_small 三个种子为
   0.4189 / 0.3642 / 0.4205（σ=0.0321，是 baseline 的 4 倍），不能写成"P2 显著提升小目标"。
5. **SimAM 的代价为零**：参数量 3,011,433 → 3,011,433（增量 0）、GFLOPs 8.2 不变；
   P2 系列参数量 2,926,956、GFLOPs 8.2 → 12.4。这条"无参数注意力"的对比优势值得强调。

## 二、方法学要点（写作时必须写明，也是本工作"无漏洞"的关键）

| 要点 | 说明 |
|------|------|
| **主表口径** | 以 **last.pt** 为主、best.pt 为辅。理由：`p2` 的 best→last 掉 **1.98 点**、`asp` 掉 2.63 点，而 `simam_p2` 只掉 0.75 点——只报 best.pt 会系统性高估并扭曲排序 |
| **两套评估口径不可混用** | 主表/分场景取 `eval_scenes.py`（ultralytics 协议）；AP_small/medium/large 取 `eval_by_size.py`（COCO 协议，faster-coco-eval）。同一 checkpoint 两者差 **0.9 点**（0.9038 vs 0.8950） |
| **显著性** | Welch t 检验（不假设方差齐性），n=3，\* p<0.05、\*\* p<0.01，其余标 n.s. |
| **报误差棒** | 所有指标给 mean ± std，不用单点最好值 |
| **分布外场景单列** | sunny / cloudy / night / rainy 四个场景分别给指标与显著性，而不是只报整体 |

## 三、预训练初始化对比（✅ 已完成：6 变体 × 3 种子 × 25 轮）

**协议**：`yolov8n.pt` 初始化，固定 25 轮、无早停；训练期只在 **val 的 3000 张分层子集**
（每场景 750 张）上监控；最终指标在**完整 val（16645 张）**上重算（ultralytics 口径，与从零表同口径）。
数字见 `docs/论文表格.md` 表 7a（best.pt）/ 7b（last.pt）；
逐项显著性见 `runs/eval_server/significance_pre_scene_{best,last}.md` 与 `..._size_....md`。

### 3.1 整体差异全部不显著

| 口径 | baseline | 最好的变体 | 最大正向差异 |
|------|----------|-----------|-------------|
| best.pt mAP50 | 0.9100 ± 0.0060 | asp 0.9126 | +0.0026 n.s. |
| best.pt mAP50-95 | 0.7393 ± 0.0036 | **p2 0.7442 ± 0.0011**（方差最小） | +0.0050 n.s. |
| last.pt mAP50 | 0.8889 ± 0.0083 | p2 0.8958 | +0.0069 n.s. |
| last.pt mAP50-95 | 0.7209 ± 0.0103 | **simam_p2 0.7323** | **+0.0114 n.s.** |

### 3.2 全部显著项（只有 4 处，其余均 n.s.）

| 口径 | 对比 | 差异 | 方向 |
|------|------|------|------|
| best.pt | rainy mAP50-95：p2 | **+0.0205 \*** | 正 |
| best.pt | cloudy mAP50：eiou | −0.0156 \* | 负 |
| best.pt | cloudy mAP50-95：eiou | −0.0161 \* | 负 |
| last.pt | 整体 Recall：p2 | **+0.0403 \*** | 正 |
| last.pt | sunny mAP50：simam | +0.0067 \* | 正 |
| last.pt | AP_medium：simam | −0.0270 \* | 负 |

### 3.3 与从零训练表对照：两个必须写进论文的发现

**发现 1：预训练初始化抬高 baseline，却把轻量改进的增益基本吃掉**

| 同一 ultralytics 口径（best.pt） | 从零训练 100 轮 | 预训练 25 轮 |
|---|---|---|
| baseline mAP50 | 0.9038 | **0.9100**（+0.0062）|
| p2 − baseline | **+0.0113** | +0.0017 |
| simam_p2 − baseline | **+0.0078** | −0.0002 |
| asp − baseline | +0.0048 | +0.0026 |

更好的初始化把这三项轻量改进的收益大部分吸收掉了。这解释了"改进幅度看起来很小"：
不是方法无效，而是 baseline 被初始化抬到接近同一水平。

**发现 2：从零训练里"阴天显著提升"的结论在预训练下不复现**

- 从零训练：cloudy 上 `simam_p2` +0.0158\*、`asp` +0.0126\*（显著正向）；
- 预训练：同一场景两者均 n.s.，反而是 `eiou` 显著为负（−0.0156\*/−0.0161\*）。

→ 该"阴天增益"只能写成**特定初始化与训练预算下的观察**，不能写成方法的稳定属性。

### 3.4 跨两种初始化都成立的三条结论（建议作为论文主结论）

1. **P2 检测层是最稳健的改进**：从零 best.pt 的 mAP50 第一（0.9151）、预训练 best.pt 的 mAP50-95
   第一（0.7442 ± 0.0011，方差最小）、预训练 last.pt 的 mAP50 与**召回（+0.0403\*，显著）**第一。
2. **EIOU 始终没有正增益**：从零训练夜间 mAP50-95 显著下降（−0.0133\*），预训练阴天两指标显著下降
   （−0.0156\*/−0.0161\*）——如实写成负/中性结果，并说明它与其余两项改进不互补。
3. **SimAM 单独使用偏向小目标**：预训练下 AP_small 为 0.4078（best）/0.4003（last），均高于 baseline
   （0.3933/0.3806）；但整体指标不占优，last.pt 的 AP_medium 还显著更低（−0.0270\*），
   是"小目标获益、中目标受损"的权衡。

> **写作口径建议**：主结论从"组合模型全面最优"改为
> **"P2 稳定有效；SimAM 的增益依赖初始化与场景；EIOU 无正增益"**——每句都有跨口径数据支撑。

## 四、局限与未来工作（如实写，反而是加分项）

1. **整体差异全部未达显著**：两套初始化（从零 100 轮 / 预训练 25 轮）× 两种权重口径（best/last）
   共四个口径下，整体 mAP 差异全部 n.s.（最大 +0.0114）。显著结论只出现在个别场景与单项指标
   （p2 雨天 mAP50-95 +0.0205\*、p2 召回 +0.0403\*、simam 晴天 mAP50 +0.0067\*、
   eiou 阴天 −0.0156\*/−0.0161\*、simam AP_medium −0.0270\*）。
   → 论文应表述为"方向一致的正向趋势 + 若干具体显著的场景/指标"，**不要声称全面超越**。
2. **预训练表存在预算内过拟合**：25 轮下监控曲线在第 5~15 轮见顶后回落（4 个变体掉 1.2~2.1 点），
   末轮权重并非最优；这正是同时报告 best/last 的原因。未来应改用早停或更短预算并给出收敛曲线。
3. **轻量改进的增益被更好的初始化吸收**：预训练把 baseline 抬高 +0.0062 mAP50，
   同时把 p2−baseline 从 +0.0113 压到 +0.0017。后续工作应在更强的 baseline（更大模型/更多数据）上
   重新验证这些模块是否仍有价值。
4. **P2 头的开销**：新增 P2 检测层使 GFLOPs 从 8.2 升到 12.4（+51%），训练显存翻倍
   （batch 需从 32 降到 16，实测单轮耗时增加约 33%）；虽然参数量略降，但推理成本上升，
   论文中应给出速度/精度权衡。
5. **EIOU 与其余改进不互补**：如需保留 EIOU，应单独调整 `box` 损失权重后重新消融。
6. **场景划分依赖官方天气标注**：UA-DETRAC 的 `sence_weather` 只有 sunny/cloudy/night/rainy
   四类，未细分雨量、能见度等；"阴天增益"这类结论对场景定义敏感。

## 五、可复现性说明（可直接写进论文附录）

- **数据**：UA-DETRAC，48 训练序列 / 12 验证序列，65356 / 16645 张；验证集每场景 3 个序列。
- **随机性**：每个变体独立跑 3 个随机种子（0/1/2），报告 mean ± std；显著性用 Welch t 检验。
- **从零训练表**：imgsz 640，100 轮（patience=20），batch 32（baseline/simam/eiou）、
  16（p2/simam_p2/asp），RTX 4060 Laptop。
- **预训练表**：`yolov8n.pt` 初始化，固定 25 轮、无早停，训练期仅在 val 的 3000 张分层子集上监控
  （正式指标一律在完整 val 上重算），RTX 4090 D；`nbs=64` 保证两套 batch 的有效批大小恒为 64
  （batch 16 → accumulate 4，batch 32 → accumulate 2），优化步数与学习率调度完全一致。
- **代码**：`configs/`（模型结构）、`scripts/train.py`（训练）、`scripts/eval_scenes.py` /
  `eval_by_size.py`（两套口径的评估）、`scripts/analyze_significance.py`（显著性）、
  `scripts/make_paper_tables.py`（一键出表）、`scripts/run_matrix_parallel.py`（多种子矩阵）。
- **两套评估口径不可混用**：主表/分场景用 ultralytics 协议（`eval_scenes.py`），
  AP_small/medium/large 用 COCO 协议（`eval_by_size.py`）；同一 checkpoint 两者相差约 0.9 个点。
- **服务器实验的环境扰动（如实交代）**：4090D 上 3 并发时显存接近上限（24.0/24.5 GB），
  在 18 次训练、约 450 个 epoch 中仅出现 **3 次** ultralytics 自适应回退
  （1 次 OOM 自动降批 + 2 次 TaskAlignedAssigner OOM），每次影响不超过一个 epoch 的计算路径，
  不改变 batch / 有效批大小 / 学习率调度。
